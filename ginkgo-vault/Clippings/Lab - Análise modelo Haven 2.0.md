## 4) APIs reais para o ecossistema HAVEN

### 4.1. Identidade, login e assinatura gov.br

1. **Login Único gov.br (OIDC/OAuth2)**
	- É a base de tudo: você integra sua aplicação como “cliente” do gov.br, usa OpenID Connect, recebe o token e os dados do cidadão. [Acesso Gov+1](https://acesso.gov.br/roteiro-tecnico/?utm_source=chatgpt.com)
		- Há um **catálogo de APIs de Acesso gov.br** (contas, confiabilidades, categorias), incluindo gestão de contas, selos de confiabilidade (nível prata/ouro), vinculação de empresas etc. [Serviços e Informações do Brasil](https://www.gov.br/conecta/catalogo/apis/brasil-cidadao-login-unico?utm_source=chatgpt.com)
		- Uso na Haven:
		- Onboarding com “Entrar com gov.br”
				- Recuperar CPF, nome, e nível de confiabilidade
				- Base para KYC forte.
2. **API de Assinatura Digital gov.br**
	- É a API para solicitar e validar **assinatura eletrônica com o certificado gov.br**, usando a conta do cidadão. [manual-integracao-assinatura-eletronica.servicos.gov.br](https://manual-integracao-assinatura-eletronica.servicos.gov.br/?utm_source=chatgpt.com)
		- Você consegue:
		- Enviar um documento (hash ou PDF) para assinatura
				- Solicitar autenticação gov.br do usuário
				- Verificar nível da conta e status da assinatura
		- Uso na Haven:
		- Assinatura de contratos, termos de adesão, autorizações, etc., em paralelo a e-Notariado/privados.
3. **Portal de Serviços / API de Acompanhamento GOV.BR**
	- API de acompanhamento de serviços digitais, desenhada pra gov, mas você pode se inspirar ou, em algum momento, integrar se tiver serviço público vinculado. [servicosgovbr.github.io](https://servicosgovbr.github.io/?utm_source=chatgpt.com)
		- Menos crítico no início, mais para quando houver fluxo com serviço público formal.

---

### 4.2. e-Notariado (cartórios de notas)

1. **e-Not Assina – Integração por API (Empresas Mensalistas)**
	- O e-Notariado oferece integração via API para empresas (“e-Not Assina Empresas Mensalistas”). [Colégio Notarial do Brasil](https://suporte.notariado.org.br/support/solutions/articles/43000699665-e-not-assina-empresas-mensalistas-integrac%C3%A3o-por-api?utm_source=chatgpt.com)
		- Permite:
		- Criar fluxos de assinatura eletrônica dentro do e-Notariado
				- Enviar documentos para assinatura
				- Baixar documentos assinados
		- Requisitos:
		- Ser empresa conveniada / mensalista
				- Gerar **chave de integração** para autenticação nas requisições
		- Uso na Haven:
		- Criar fluxo de assinatura de escritura / instrumentos contratuais dentro do padrão notarial
				- Integrar com RI Digital (ver abaixo) através do ecossistema notarial.

---

### 4.3. SREI / ONR / RI Digital (registros de imóveis)

1. **ONR (Operador Nacional do Sistema de Registro Eletrônico de Imóveis)**
	- Responsável por implementar e operar o **SREI** nacionalmente. [Registro de Imóveis+1](https://www.registrodeimoveis.org.br/onr?utm_source=chatgpt.com)
		- O SREI oferece serviços online como pedido de certidões, visualização eletrônica da matrícula, pesquisa de bens por CPF/CNPJ etc. [CNJ](https://www.cnj.jus.br/sistemas/sistema-de-registro-eletronico-de-imoveis-srei/?utm_source=chatgpt.com)
2. **RI Digital + APIs ONR (para desenvolvedores)**
	- Há manuais e APIs voltadas para **cartórios e empresas de software que atendem cartórios**, com foco em integração com os serviços do Registro de Imóveis do Brasil. [Registro de Imóveis+1](https://www.registrodeimoveis.org.br/intranet/arquivos/upload/geral/999999_upload_de_arquivos_geral_20250307_110800_bcdd95f7-925c-41f2-99d3-126ae593c0d3.pdf?utm_source=chatgpt.com)
		- Funcionalidades típicas:
		- Envio de títulos/solicitações para registro
				- Acompanhamento de andamento
				- Consulta de informações/matrículas
		- Observação importante:
		- Essas integrações não são “públicas self-service” tipo Stripe; geralmente exigem convênios, credenciamento e respeitar o papel institucional (cartório, registrador, etc.).
				- Para a Haven, o caminho prático é:
			- ou você se credencia formalmente
						- ou se integra a um parceiro (notário/RI digital) que já tenha essa integração habilitada.
3. **Integração e-Notariado + RI Digital (ONR)**
	- e-Notariado e RI Digital hoje já são integrados entre si para envio de escrituras diretamente para registro, com manuais e vídeos oficiais. [Colégio Notarial do Brasil+3INR Publicações+3Tribunal de Justiça do Maranhão+3](https://inrpublicacoes.com.br/site/boletim/noticia/35795/integrao-entre-e-notariado-e-ri-digital-conta-com-vdeos-tutoriais-e-manual-de-apoio--cnb.?utm_source=chatgpt.com)
		- Na prática:
		- Você usa a API do e-Notariado para montar e assinar a escritura
				- O próprio ecossistema e-Notariado/RI Digital faz o envio ao registro de imóveis.
		- Para Haven, isso é perfeito: você foca no **front e orquestração**, e deixa a “perna registral” com quem já tem a infra oficial.

### 4.4. Camada privada complementar (não estatal, mas crítica)

Aqui não é governo, mas é essencial na arquitetura:

- **Clicksign/DocuSign/ZoopSign** – assinatura eletrônica avançada para contratos comerciais, termos internos, etc.
- **PSPs / gateways** (Pagar.me, Stripe, Asaas etc.) – para pagamentos Pix, cartão, boletos.
- **Exchanges / custodians de cripto** – Binance, Mercado Bitcoin, Foxbit, ou custodiante regulado, com APIs para conversão instantânea em BRL e relatório de origem de fundos.

## 5) Arquitetura de backend: Haven + Supabase + n8n + Keycloak + gov.br

Vou montar a arquitetura como “camadas” + fluxo típico.

### 5.1. Visão em camadas

**Camada 0 – Clientes**

- App mobile (Flutter/React Native)
- Web app (Next.js/React)
- Painel interno Haven (admin / compliance)

Todos falam com o backend via API Gateway/BFF e usam fluxo de login que termina em **Keycloak**.

---

**Camada 1 – Autenticação e Identidade**

- **Keycloak** como “cérebro de identidade” da Haven:
	- SSO, RBAC, gestão de roles (buyer, seller, admin, compliance etc.)
		- Cliente OIDC para gov.br (Login Único):
		- gov.br é IdP externo
				- Keycloak é “broker de identidade” que recebe tokens do gov.br e emite seus próprios tokens JWT para seus serviços. [Acesso Gov+1](https://acesso.gov.br/roteiro-tecnico/?utm_source=chatgpt.com)
- Fluxo:
	1. Usuário clica em: “Entrar com gov.br”
		2. Front redireciona para gov.br
		3. gov.br autentica, retorna para Keycloak
		4. Keycloak cria/atualiza usuário interno, adiciona claims (CPF, nome, nível de confiabilidade)
		5. Emite access token da Haven → usado em todas as APIs internas.
- Supabase aqui **não faz auth**; ele é “apenas” banco relacional e storage.

---

**Camada 2 – Serviços de Negócio (microserviços ou módulos)**

Sugestão mínima de serviços:

1. **User & KYC Service**
	- Banco: tabelas em Supabase (users, kyc\_checks, govbr\_accounts, risk\_flags)
		- Funções:
		- armazenar dados complementares (endereço, renda declarada, PEP, etc.)
				- consolidar informações de gov.br, CNH digital, e outras fontes
				- expor status de KYC para outros serviços.
2. **Property Service (Imóveis)**
	- Tabelas: properties, owners, listings, documents, registry\_refs
		- Funções:
		- cadastro e gestão de imóveis
				- associar docs (matrícula, certidões, laudos)
				- guardar referência a protocolos no SREI/RI Digital (quando houver).
3. **Wallet & Payments Service**
	- Ledger interno em Postgres (Supabase): accounts, balances, transactions, fx\_quotes
		- Conectores:
		- PSPs (Pix, cartão)
				- Exchanges (cripto → BRL)
		- Funções:
		- controlar saldos e movimentações
				- montar “cesta de pagamento” (X BRL + Y USD + Z cripto)
				- chamar conversão FX/cripto e registrar custo efetivo.
4. **Contracts & Signature Service**
	- Integra com:
		- API de Assinatura Digital gov.br [manual-integracao-assinatura-eletronica.servicos.gov.br](https://manual-integracao-assinatura-eletronica.servicos.gov.br/?utm_source=chatgpt.com)
				- e-Not Assina (e-Notariado) [Colégio Notarial do Brasil](https://suporte.notariado.org.br/support/solutions/articles/43000699665-e-not-assina-empresas-mensalistas-integrac%C3%A3o-por-api?utm_source=chatgpt.com)
				- Clicksign/DocuSign (camada privada)
		- Funções:
		- gerar minutas (templates em banco + placeholders)
				- registrar hashes dos documentos
				- disparar fluxo de assinatura (gov.br / e-Notariado / privado)
				- armazenar URLs e PDFs finais em Supabase Storage (criptografado).
5. **Registry Integration Service**
	- Integra com:
		- ONR / SREI / RI Digital (direto ou via parceiro), usando documentação de integração para cartórios/sistemas. [Registro de Imóveis+1](https://www.registrodeimoveis.org.br/intranet/arquivos/upload/geral/999999_upload_de_arquivos_geral_20250307_110800_bcdd95f7-925c-41f2-99d3-126ae593c0d3.pdf?utm_source=chatgpt.com)
		- Funções:
		- enviar títulos para registro
				- receber e atualizar status (protocolado, registrado, devolvido, exigência etc.)
				- armazenar número de matrícula/registro final.
6. **Notification & Comms Service**
	- Integra com:
		- WhatsApp (Evolution API / Brann)
				- e-mail (SMTP / provider)
				- push notifications
		- Funções:
		- enviar status de processo para o cliente
				- mandar lembretes, confirmações, exigências.
7. **Compliance & Audit Service**
	- Log centralizado (auditoria)
		- Eventos relevantes: login, KYC, transações, assinaturas, registros
		- Base para relatórios de PLD/AML.

Todos esses serviços usam **Postgres do Supabase** como base principal de dados, com schemas separados por domínio (ex: auth\_, core\_, registry\_, etc.).

---

**Camada 3 – Orquestração de Fluxos (n8n)**

O n8n entra como “motor de automação” e cola todos os serviços:

- Triggers:
	- Webhooks do backend (ex: “nova proposta aprovada”)
		- Webhooks externos (e-Notariado, PSP, RI Digital, gov.br assinatura)
- Ações:
	- Chamar APIs internas (User Service, Wallet, Contracts)
		- Chamar APIs externas (gov.br, e-Notariado, ONR, PSPs, exchanges) via HTTP Node
		- Escrever/ler no Supabase (nodes oficiais)
		- Notificar via WhatsApp, e-mail, push

Exemplo de fluxo no n8n (simplificado):

1. Evento: “Compra aprovada pelo cliente” (webhook do backend)
2. Node: Consulta User & KYC → garante que está todo OK
3. Node: Monta cesta de pagamento (Wallet Service)
4. Node: Faz chamadas de conversão (PSP + exchange)
5. Node: Chama Contracts Service → gera minuta
6. Node: Chama API gov.br/e-Notariado para assinatura
7. Node: Após assinatura, chama Registry Service (RI Digital/ONR)
8. Node: Ao registrar, grava registro em Supabase e dispara notificação.

n8n vira o **“core de processos”** da Haven, deixando o backend mais limpo e desacoplado.

---

**Camada 4 – Infraestrutura e Segurança**

- **API Gateway / BFF**
	- Pode ser Kong, Traefik, ou BFF em Node/NestJS
		- Valida JWT do Keycloak, faz rate limit, logging etc.
- **Keycloak**
	- Rodando em container (Docker/EasyPanel)
		- Realm “haven” com clients (mobile, web, painel, n8n)
		- Identity provider gov.br configurado (OIDC).
- **Supabase**
	- Usado como Postgres gerenciado + Storage
		- SCHEMAS por domínio
		- RLS (Row Level Security) pode ser usado via JWT de serviço (não o JWT público do Keycloak; você gera tokens de serviço para o backend).
- **n8n**
	- Rodando em container próprio
		- Autenticado via API Key/JWT com os serviços internos
		- Conectado ao Supabase via credenciais de serviço.
- **Observabilidade**
	- Logging centralizado (Grafana Loki/ELK)
		- Métricas (Prometheus/Grafana)
		- Tracing (Jaeger/OpenTelemetry) se quiser ir pro nível high-end.

### 5.2. Fluxo típico de compra na prática (alto nível)

1. Usuário abre app → “Entrar com gov.br”
2. Keycloak faz broker com gov.br, retorna token Haven
3. Backend cria/atualiza perfil + registra nível de confiabilidade gov.br
4. Usuário escolhe imóvel → Property Service
5. Gabriel IA (Brann + Manus) guia a negociação
6. Ao confirmar a compra:
	- Backend dispara evento → n8n
		- n8n valida KYC → User Service
		- n8n monta pagamento → Wallet Service (PSP + exchanges)
		- n8n gera contrato → Contracts Service
		- n8n aciona gov.br Assinatura + e-Notariado
		- Após assinatura, n8n aciona Registry Service (RI Digital/ONR)
		- Ao registrar, grava registro/finalização → Supabase
		- Notification Service avisa o cliente: “Registro concluído. Seu imóvel está no seu nome.”

Tudo logado, auditado e com respaldo jurídico.
